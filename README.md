# 同频猜词

一个房间内所有人写同一个词。没有话题，没有提示，只能靠默契。

昵称留空会从热梗昵称池随机分配，同房间自动分配的昵称不重名，断线重连保留昵称；自定义昵称照常使用。

## 玩法

首页「规」可查看规则说明。默认每次进入首页自动展示，勾选弹窗底部悬浮栏中的「下次不再弹出」后在当前浏览器记住选择；仍可手动打开并取消勾选。恢复已有房间时不会自动展示。

1. 房主创建房间，设置人数上限（2-8）和每轮限时
2. 把邀请链接或 4 位房间码发给其他人
3. 每轮所有人同时提交一个词，提交后不可修改，也看不到别人写了什么
4. 全部提交完立刻结算，服务器判断是否完全一致

两条出路：

- **完全一致**：服务器直接判定成功，本局当场结束，没有投票环节
- **不一致**：自动进入下一轮，新一轮的输入页会显示上一轮的完整结果，任何人可以在那里点「这轮算同频？」投出一票。所有人认定，本局结束

第二条出路是给「土豆 / 马铃薯」这种字面不同但意思一样的情况准备的。服务器只认字面，认不认定由玩家决定，所以一局可能一轮就结束，也可能拖很久。

**已经出现过的词不能再用**，同一轮内允许重复。

## 结果展示

结算页显示本局总轮数与成功轮结果，更早的收在「回看调频现场（N 轮）」里。游戏中可以上下滚动查看历史轮次。两人局的历史记录隐藏名称，成功轮结果保留名称。

结束文案分两套：服务器判定一致的是「脑回路，接上了。」，玩家投票认定的是「系统没懂，你们懂了。」。

「再来一局」需要至少两名在线玩家全员准备，点击可准备或取消，按钮下方显示准备人数与各自状态。临时断线会取消该玩家的准备，重连后可重新准备。

仅在游戏进行中，右上角的连接状态与主题按钮之间显示退出图标；等待页和结算页通过「返回主页」退出。房主和普通玩家退出前都会二次确认：房主确认后解散房间，所有人返回首页；普通玩家确认后自己返回首页，其他人回到原房间等待页，准备状态和对局进度清空。临时断线仍保留重连位置。

临时关闭网页后，用同一浏览器、同一网站地址重新打开，即使网址不带房间码，也会自动恢复上次的房间、昵称和房主身份。所有人离线后房间保留约 10 分钟；仍有人在线时可以继续重连，但房间总寿命最长 6 小时，服务器重启也会清空房间。主动退出或房主解散后不会自动恢复；打开另一个房间的邀请链接时优先显示该邀请，仍需点击加入。

## 本地战绩

首页标题右侧的「历」字按钮可打开本地战绩，列表显示完成时间、总轮数、参与者名称和最终答案，答案使用对应颜色的边框并以 × 连接。点击可回看每一轮；名字仅在最终结果显示，逐轮记录隐藏名字，回看页也隐藏顶部的本地存储说明。

只有完全一致或全员认定的成功对局会保存；中途有玩家断线（包括刷新重连）或主动退出的对局不留存。完成后才断线或返回主页不影响已保存的记录。同一局的准备、重连及刷新不会重复保存。

记录仅保存在当前浏览器、当前网站地址的本地存储中，不上传服务器。清除浏览器数据、使用其他浏览器或更换网站地址无法读取原有记录；无痕模式的记录可能在关闭窗口后清除。存储不可用或已满时会提示保存失败，不自动清理旧记录。

## 运行

主题切换左侧显示连接状态和心跳往返延迟：低于 200 ms 为绿色，200–499 ms 为黄色，500 ms 及以上为红色。客户端每 2 秒发送一次心跳，连接或心跳响应超过 10 秒未完成时自动重连；重连及房间同步期间，提交按钮显示 loading 并禁用，输入内容保留。

```bash
npm install
npm start        # http://localhost:3000
npm test         # 端到端自检
```

局域网测试用启动时打印的地址，不要用 localhost，否则「复制链接」拷出来的地址对方打不开。

## 运行统计

游戏首页卡片下方以小字公开展示“当前在线 · 累计开局”。统计随每 2 秒一次的心跳响应返回，不主动推送；数字变化时上下滚动切换，首次载入、数字不变或开启“减少动态效果”时不播放动画。断线时显示 `—`，避免将旧读数当作实时数据。无需额外配置密码；`/api/stats` 也只公开这两个汇总数字。

- **当前同时在线**：最近 30 秒内仍与服务器通信的网页连接，包含首页访客；同一人打开多个标签页分别计数。断开连接立即从统计中移除，异常断网约 30 秒后不再计入，页面在下一次心跳响应时更新。
- **累计开启对局**：房主正式开始，以及全员准备后成功开始的“再来一局”，各计一次。建房、进入下一轮、刷新和重连不重复计数；已开局后中途退出也保留计数。

累计数字和统计起点保存在 `data/stats.json`，从本功能首次运行开始统计，无法补算之前的对局。该目录已加入 Git 忽略；更新代码和重启时请保留并备份它，也可通过 `STATS_FILE` 指定持久化文件路径。统计仅适用于当前的单进程部署；多个独立实例的数据不会合并。不记录昵称、猜词、IP 或访问明细。

统计文件保存失败会在服务器日志提示，进程内继续累计，后续开局保存成功时会补存累计值；若保存恢复前重启，尚未落盘的新增计数会丢失。已有统计文件损坏或不可读时，服务会报错停止启动，避免覆盖旧数据。

## PM2 部署

服务器已安装 Node.js 和 PM2 后，在项目目录执行：

```bash
npm ci --omit=dev
pm2 start ecosystem.config.cjs
pm2 save
```

部署时一并上传 `ecosystem.config.cjs`。该配置使用单进程，监听 **3001** 端口；Nginx 的 `proxy_pass` 对应设置为 `http://127.0.0.1:3001`，并保留 WebSocket 转发配置。

查看日志用 `pm2 logs same-word-game`，更新代码后用 `pm2 restart ecosystem.config.cjs`。重启会清空现有房间。需要开机启动时，执行 `pm2 startup` 并按提示完成系统配置。

## 设计取舍

- 游戏界面仍为原生 HTML/JavaScript；全屏背景单独挂载 React Bits GridScan（JS-CSS），随深浅主题切换配色，尊重减少动态效果设置。组件位于 `src/components/`，网格空间在宽度小于 768px 时保持竖向长方形，桌面端跟随视口呈横向矩形，扫描框均保持向纵深推进；上游来源：https://reactbits.dev/r/GridScan-JS-CSS.json
- 背景通过 React 和 esbuild 打包为本地资源，不依赖运行时 CDN；修改 `src/` 后执行 `npm run build`，部署时一并上传 `public/assets/` 中的 JS 和 CSS。仓库保留构建产物，生产环境 `npm ci --omit=dev` 后可直接启动
- 房间状态在进程内存里，重启即丢。房间里没有值得落库的东西
- 词比较前做 NFKC + 去空白 + 转小写，所以 `Apple` 和 `apple ` 视为同一个词
- 本轮已提交的词绝不下发，只有结算完的轮次才进入下发给客户端的历史
- 超时和掉线的人视为弃权，不阻塞其余人；人数不足 2 人时回合不推进
- 折叠用原生 `<details>`，配合实际高度动画兼容手机浏览器
- 测试用随机端口并对退出做清理，避免断言失败时留下孤儿进程占着端口跑旧代码
