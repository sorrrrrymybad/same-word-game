# 同频猜词

一个房间内所有人写同一个词。没有话题，没有提示，只能靠默契。

昵称留空会从热梗昵称池随机分配，同房间自动分配的昵称不重名，断线重连保留昵称；自定义昵称照常使用。

玩家头像使用 [DiceBear Fun Emoji](https://www.dicebear.com/styles/fun-emoji/)，以完整昵称为种子，相同昵称生成相同头像。图片通过 DiceBear 公共接口加载，昵称会作为请求参数发送给该服务；头像加载依赖外部网络。图案由 Davis Uche 创作，采用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 授权。

砸番茄的像素贴图及飞溅逻辑改编自 Quinten Clause 的 [Tomato Smash](https://github.com/quinten/tomato-smash)（MIT），素材和授权声明位于 `public/assets/tomato.png`、`public/assets/tomato-smash-LICENSE.txt`。保留从发送者头像飞到目标头像的一次飞行；到达后，仅接收者看到一颗番茄从屏幕深处飞近、自动爆开并消失，不循环。开启“减少动态效果”时跳过飞行，仅显示淡出的番茄汁。

## 玩法

首页「规」可查看规则说明。默认每次进入首页自动展示，勾选弹窗底部悬浮栏中的「下次不再弹出」后在当前浏览器记住选择；仍可手动打开并取消勾选。恢复已有房间时不会自动展示。

1. 房主创建房间，设置人数上限（2-8）和每轮限时
2. 把邀请链接或 4 位房间码发给其他人
3. 每轮所有人同时提交一个词，提交后不可修改，也看不到别人写了什么
4. 全部提交完立刻结算，服务器判断是否完全一致

两条出路：

- **完全一致**：服务器直接判定成功，本局当场结束，没有投票环节
- **不一致**：自动进入下一轮，新一轮的输入页会显示上一轮的完整结果，任何人可以在那里点「这轮算同频？」投出一票。所有人认定，本局结束

第二条出路是给「土豆 / 马铃薯」这种字面不同但意思一样的情况准备的。服务器只认字面，认不认定由玩家决定，所以一局可能一轮就结束，也可能拖很久。

**已经出现过的词不能再用**，同一轮内允许重复。

## 结果展示

结算页显示本局总轮数与成功轮结果，更早的收在「回看调频现场（N 轮）」里。游戏中可以上下滚动查看历史轮次。两人局的历史记录隐藏名称，成功轮结果保留名称。

结束文案分两套：服务器判定一致的是「脑回路，接上了。」，玩家投票认定的是「系统没懂，你们懂了。」。

「再来一局」需要至少两名在线玩家全员准备，点击可准备或取消，按钮下方显示准备人数与各自状态。临时断线会取消该玩家的准备，重连后可重新准备。

仅在游戏进行中，右上角的连接状态与主题按钮之间显示退出图标；等待页和结算页通过「返回主页」退出。房主和普通玩家退出前都会二次确认：房主确认后解散房间，所有人返回首页；普通玩家确认后自己返回首页，其他人回到原房间等待页，准备状态和对局进度清空。临时断线仍保留重连位置。

临时关闭网页后，用同一浏览器、同一网站地址重新打开，即使网址不带房间码，也会自动恢复上次的房间、昵称和房主身份。所有人离线后房间保留约 10 分钟；仍有人在线时可以继续重连，但房间总寿命最长 6 小时，服务器重启也会清空房间。主动退出或房主解散后不会自动恢复；打开另一个房间的邀请链接时优先显示该邀请，仍需点击加入。

## 本地战绩

首页标题右侧的「历」字按钮可打开本地战绩，列表显示完成时间、总轮数、参与者名称和最终答案，答案使用对应颜色的边框并以 × 连接。点击可回看每一轮；名字仅在最终结果显示，逐轮记录隐藏名字，回看页也隐藏顶部的本地存储说明。

只有完全一致或全员认定的成功对局会保存；中途断线或刷新后重连不影响保存，但成功结算时本局实际参与过的玩家必须全部在线且都在成功轮结果中。多人局有人离线时，即使剩余玩家同频进入结果页，也不会保存，事后重连不补存。主动退出仍会清空当前对局，不留战绩。完成后才断线或返回主页不影响已保存的记录。同一局的准备、重连及刷新不会重复保存。

此处展示的战绩保存在当前浏览器、当前网站地址的本地存储中。清除浏览器数据、使用其他浏览器或更换网站地址无法读取原有记录；无痕模式的记录可能在关闭窗口后清除。存储不可用或已满时会提示保存失败，不自动清理旧记录。服务器另行保存对局及参与者 IP，用于运行记录，不提供公开查询或跨浏览器恢复。

## 运行

主题切换左侧显示连接状态和心跳往返延迟：低于 200 ms 为绿色，200–499 ms 为黄色，500 ms 及以上为红色。客户端每 2 秒发送一次心跳，连接或心跳响应超过 10 秒未完成时自动重连；重连及房间同步期间，提交按钮显示 loading 并禁用，输入内容保留。

```bash
node --version  # 需要 Node.js 24 或更新版本，使用内置 node:sqlite
npm install
npm start        # http://localhost:3000
npm test         # 端到端自检
```

局域网测试用启动时打印的地址，不要用 localhost，否则「复制链接」拷出来的地址对方打不开。

## 页面更新提示

页面每 30 秒检查一次 HTML 内容版本，发现更新后显示「刷新更新」，不会自动刷新。对局中刷新需要再次确认，并提醒未提交的词会清空；重连后完成仍可保存，但离线期间缺人完成的对局不保存。直接更新 HTML 即可被检测，无需手动维护版本号或重启服务。

首次部署此功能时，已经打开的旧页面仍需手动刷新一次，之后才能接收更新提示。此检测只覆盖 HTML；修改背景资源时仍按下方说明构建和部署。

## 运行统计

游戏首页卡片下方以小字公开展示“当前在线 · 累计开局”。统计随每 2 秒一次的心跳响应返回，不主动推送；数字变化时上下滚动切换，首次载入、数字不变或开启“减少动态效果”时不播放动画。断线时显示 `—`，避免将旧读数当作实时数据。无需额外配置密码；`/api/stats` 也只公开这两个汇总数字。

- **当前同时在线**：最近 30 秒内仍与服务器通信的网页连接，包含首页访客；同一人打开多个标签页分别计数。断开连接立即从统计中移除，异常断网约 30 秒后不再计入，页面在下一次心跳响应时更新。
- **累计开启对局**：房主正式开始，以及全员准备后成功开始的“再来一局”，各计一次。建房、进入下一轮、刷新和重连不重复计数；已开局后中途退出也保留计数。

统计及对局历史保存在 SQLite 数据库 `data/game.sqlite`，使用 Node.js 内置 SQLite，无需额外安装数据库服务。首页文案为“全网已开局”，沿用原有累计开局口径，不另存同频总数。

- `metrics` 表：`started_games` 总开局数、`site_visits` 总访问数；各自包含 `value`、统计起点 `since`、最后更新时间 `updated_at`。访问量按成功返回首页 `/` 或邀请页 `/r/...` 的 GET 请求计数，刷新及同一人多次访问分别累加；接口、静态资源和 HEAD 请求不计数，不做独立访客去重。
- `games` 表：每次正式开局或再来一局新增一行，保存 `id`、房间码、开局时间 `started_at`、开局在线人数 `player_count`、参与者 `players_json`（公开 ID、昵称、首次参与时的 IP）、已结算轮次 `history_json`、当前轮已提交答案及投票 `current_round_json`、更新时间、结束时间及结果。临时掉线、刷新和重连继续更新同一行；开局时离线的老玩家之后重连参与，会追加到参与者列表，开局人数保持原值。私密重连令牌不入库。
- 对局状态：`play` 进行中、`done` 完成、`aborted` 主动退出/解散/过期、`interrupted` 服务重启中断。每轮结算、提交、投票都会保存；中断也保留此前内容。完成原因 `ended_by` 为 `match` 或 `accepted`。数据库历史不用于恢复实时房间。
- 每 60 秒在服务日志输出一次 `[online] <北京时间> count=<当前在线数>`，如 `[online] 2026-11-14T00:30:00+08:00 count=7`；固定使用 `Asia/Shanghai`，不依赖服务器系统时区，与首页使用同一在线口径，不写入数据库。

数据库时间统一使用带 `+08:00` 的北京时间 ISO 8601 字符串，保留毫秒，不依赖 `TZ` 环境变量。启动时自动将旧版以 `Z` 结尾的 UTC 时间转换为北京时间表示，保留原实际时刻，不改变累计值或对局内容，重复启动不会再次加八小时。首次启动自动将旧 `data/stats.json` 中的 `startedGames` 和 `since` 迁入总开局数，保留原 JSON 文件作为备份；后续启动只读 SQLite，不再读写 JSON。原始计数的最后更新时间未知，迁移时以当前时间记录。访问量和逐局历史从本次升级开始统计，无法补算历史。没有旧文件时从零开始；旧文件损坏或不可读时停止迁移并报错，修复后可重试。

可通过 `DATABASE_FILE` 指定数据库位置；`STATS_FILE` 仅指定旧 JSON 的迁移来源，未设置 `DATABASE_FILE` 时数据库默认放在该 JSON 同目录。开局历史与总数在同一事务内写入，失败会回滚；数据库损坏或对局写入失败会报错停止服务，避免悄悄丢失统计。访问计数失败则返回 503 并记录错误。该实现延续单进程部署。

`data/` 已被 Git 忽略。数据库使用适合单进程的 DELETE 日志模式，提交的数据直接存入 `game.sqlite`；备份时仍需先停服务再复制，避免复制过程中遇到写入。旧版 WAL 模式升级时须保留原库及同目录的 `game.sqlite-wal`、`game.sqlite-shm`，新版首次启动会将已提交的 WAL 数据合并到主文件并切换模式，不能手动删除 WAL 或用单独下载的空主文件覆盖原库。服务器历史包含 IP 和答案，请仅通过服务器文件权限控制访问；公开 `/api/stats` 和心跳仍只返回在线数与总开局数。

直接启动时默认记录连接 IP。PM2 配置已开启 `TRUST_PROXY=1`，仅当连接来自本机 `127.0.0.1` 或 `::1` 时读取转发头；Nginx 需设置 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`，服务验证并读取该头的最后一个 IP。此配置适用于单层本机代理；其他来源或无效转发头回退到连接 IP，未开启时始终忽略转发头。

## PM2 部署

服务器已安装 Node.js 24+ 和 PM2 后，在项目目录执行：

```bash
npm ci --omit=dev
pm2 start ecosystem.config.cjs
pm2 save
```

部署时一并上传 `ecosystem.config.cjs`。该配置使用单进程，监听 **3001** 端口；Nginx 的 `proxy_pass` 对应设置为 `http://127.0.0.1:3001`，并保留 WebSocket 转发配置。

查看日志用 `pm2 logs same-word-game`，更新代码后用 `pm2 restart ecosystem.config.cjs`。重启会清空现有房间。需要开机启动时，执行 `pm2 startup` 并按提示完成系统配置。

## 设计取舍

- 游戏界面仍为原生 HTML/JavaScript；全屏背景单独挂载 React Bits GridScan（JS-CSS），随深浅主题切换配色，尊重减少动态效果设置。组件位于 `src/components/`，网格空间在宽度小于 768px 时保持竖向长方形，桌面端跟随视口呈横向矩形，扫描框均保持向纵深推进；上游来源：https://reactbits.dev/r/GridScan-JS-CSS.json
- 背景通过 React 和 esbuild 打包为本地资源，不依赖运行时 CDN；修改 `src/` 后执行 `npm run build`，部署时一并上传 `public/assets/` 中的 JS 和 CSS。仓库保留构建产物，生产环境 `npm ci --omit=dev` 后可直接启动
- 实时房间状态在进程内存里，重启即丢；统计和对局历史写入 SQLite，重启后保留
- 词比较前做 NFKC + 去空白 + 转小写，所以 `Apple` 和 `apple ` 视为同一个词
- 本轮已提交的词绝不下发，只有结算完的轮次才进入下发给客户端的历史
- 超时和掉线的人视为弃权，不阻塞其余人；人数不足 2 人时回合不推进，重连恢复到至少 2 人后补结算已超时的回合
- 公开玩家 ID 与私密重连令牌分离，房间状态和历史不下发令牌；同一连接需先退出当前房间才能建房或切换房间
- 折叠用原生 `<details>`，配合实际高度动画兼容手机浏览器
- 测试用随机端口并对退出做清理，避免断言失败时留下孤儿进程占着端口跑旧代码
